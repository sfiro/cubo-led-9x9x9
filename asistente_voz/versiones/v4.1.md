# Versión 4.1: el modo demo dice el nombre de cada animación

**Etiqueta:** `asistente-v4.1` · **Fecha:** 2026-11-16 · **Basada en:** [v4.0](v4.md)

Cuando pides todas las animaciones ("modo demo", "pon todas las animaciones", "sorpréndeme"),
el cubo dice el nombre de cada una antes de mostrarla: "Ahora, la lluvia", "Ahora, los fuegos
artificiales"…

## Cómo se usa
- "Hola cubo, modo demo": contesta "Listo, pongo todas las animaciones", y luego por cada
  animación:
  1. dice "Ahora, …" (mientras habla, el cubo muestra la voz);
  2. muestra la animación completa;
  3. sigue con la siguiente.
- "Para" la detiene, igual que antes.
- Para que el demo no hable, pon `ANUNCIAR_DEMO = False` en `config.py`. Si no está, vale
  `True`.

Los nombres son los de la tabla de comandos de la [v2](v2.md) ("la tormenta", "el
cubo giratorio", "la burbuja"…). Puedes pedir cada animación con el mismo nombre que dice.

## Cómo funciona
- `MotorAnimaciones` recibe una función `al_empezar`. En el modo demo la llama antes de cada
  animación, en otro hilo (`run_in_executor`), y espera a que termine. Así la animación
  empieza justo cuando termina de decir el nombre, y el motor no se frena.
- Antes del anuncio el cubo se apaga, para que no quede congelado el último cuadro de la
  animación anterior.
- **No se escucha a sí mismo:** el micrófono descarta lo que entra mientras suena el parlante,
  y 0.4 s después (`Reproductor.ocupado()`). Sin esto, estando despierto oiría "Ahora, la
  lluvia" y lo tomaría como el comando "lluvia", que corta el demo.
- **No se mezcla con las respuestas:** un candado (`turno`) hace que un anuncio espere a que
  termine la respuesta que el asistente esté dando, y al revés.

## Cambios en el código

| Archivo | Cambio |
|---|---|
| `raspberry/animaciones_pi.py` | `MotorAnimaciones(al_empezar=…)`, llamada antes de cada animación del demo |
| `raspberry/asistente.py` | `VERSION = "4.1"`, función `anunciar`, candado `turno`. `escuchar_pregunta(rep=…)` descarta el audio mientras suena el parlante |
| `raspberry/audio.py` | `Reproductor.ocupado(margen_s)` |
| `raspberry/comandos.py` | `nombre_hablado(nombre)` |
| `raspberry/config_ejemplo.py` | `ANUNCIAR_DEMO = True` |

## Actualizar desde la v4.0
```bash
cd ~/cubo-led-9x9x9 && git pull
```
Luego reinicia el asistente. No hay que cambiar `config.py` ni volver a cargar la Pico.

## Cómo se probó
En la Mac, con `--escribir`, una voz y un parlante simulados, y animaciones acortadas a 0.2 s:
- "Hola cubo, modo demo" responde y anuncia "Ahora, la marquesina", "Ahora, el cubo
  giratorio", "Ahora, las cajas"…, una por animación y en orden.
- "Para" detiene el demo y no se anuncia ninguna más.
- La respuesta "Listo, pongo todas las animaciones" sale antes del primer anuncio, no en medio.
- Con un micrófono simulado que oye 1.2 s del anuncio y luego 0.6 s de una persona, solo se
  graba lo de la persona.

Falta probar en la Pi con el parlante real, para revisar que el eco del anuncio no alcance a
despertar el micrófono. Si pasa, hay que subir el margen de `ocupado()`.
